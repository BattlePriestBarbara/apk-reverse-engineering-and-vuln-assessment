> **一句话结论**：加固壳本身质量不低（DEX 方法体加密 + VMP + 反调试，静态与动态都拦住了），
> 但**壳之外的一切几乎全部失守** —— 网关签名密钥随包分发且四套环境复用、全域允许明文 HTTP、
> 导出组件无权限约束。三层分析（静态 / 动态 / 攻击模拟）独立收敛到同一根因：
> **信任锚放在了客户端里**。

## 1. 这是什么 / 不是什么

**是**：针对**单一 APK 样本**的客户端安全评估，覆盖三条相互独立的证据链 ——

1. **静态分析**：解包、二进制 AXML 树还原、DEX 字符串池、密码学材料提取、全树敏感常量扫描、离线筛查器；
2. **动态分析**：本地模拟器（LDPlayer 9 + Frida 17.18.0）上的脱壳尝试 —— 结论是**未取得明文 DEX**，
   且失败点在 ARM64 翻译层而非壳强度；
3. **零流量攻击模拟**：8 类攻击 × 3 种网关配置剖面 = 24 组断言，进程内契约复刻，全程不出网。

**不是**：服务端渗透、对生产/测试系统的在线测试、第三方平台账号操作、供应链与合规审计。
评估期间未对任何真实服务发起请求（详见《综合安全评估报告》§2 合规与边界声明）。

## 6. 脱敏与占位符

完整规则见 **`脱敏说明.md`**，此处只给使用要点：

- 正文与证据文件（13 份 `.md` / `.txt`，**不含本 README**）共 **267 处替换点、105 个不同占位符**；
  本 README 里出现的占位符仅为示例。
- **编号全局稳定**：同一原始值在全部文件中始终对应同一个占位符，因此
  「§4.1 的 `<HOST-3>`」这类跨文档交叉引用仍然成立，可直接引用。
- 主要族：`<HOST-n>`(30) `<PUBLIC_IP-n>`(13) `<PRIVATE_IP-n>`(3) `<MALFORMED_IP-n>`(3)
  `<SHA256-n>`(9) `<USCC-n>`(3) `<ACCOUNT-ID-n>`(3) `<PHONE-n>`(2)，
  以及 `<APK_DIR>` `<WORK_DIR>` `<RE_WS>` `<CERT-FINGERPRINT>` `<REDACTED-PARTIAL>`
  `<IDCARD-MASKED>` `<PHONE-MASKED>` `<TRACE-ID>` `<ACCOUNT>`。
- 凭据沿用 `[REDACTED_<KIND>:<len>]` 约定（网关签名密钥、AppSecret/AppKey/AppID、
  公钥 base64、UUID 等），**保留类别与长度**以便业务方按编号回查，不含任何原值。
- **有意保留**（不构成身份、且是判断依据）：等保 2.0 三级条款号（如 `8.1.4.2`）、
  `127.0.0.1` / `0.0.0.0`、公开 SDK 与加固产品名称、版本号与各类计数。
- ⚠️ **不要回填**：任何情况下不要把原值写回这些文档。原值映射表只在受控内部分析环境
  （`_san2/_map_report.txt`），**禁止提交到仓库或对外共享**。

## 7. 复现与再生成

> 本目录是**对外分发副本**，只含报告与已落盘的证据输出。
> 全部可执行代码（`_re_ws/` 下 41 个分析脚本、`_san2/` 下构建脚本、
> `sandbox/attack_sim.py` 与 `mock_gateway.py`）都在受控内部分析环境，
> **不随本目录分发**。下文命令均需在内部分析环境执行。

### 7.1 复核结论（需要样本与脚本）

| 目标 | 命令 |
| --- | --- |
| 离线漏洞筛查 | `python _re_ws/vuln_screen.py` |
| 攻击模拟（零流量） | `python sandbox/attack_sim.py --json sandbox/attack_result.json` |
| 单元测试 | `python -m unittest discover -s tests` |
| CVSS 反向复算 | `python _re_ws/cvss_check.py --verify threat_model.md` |
| 证据四元组审计 | `python qa_evidence.py` |

不需要脚本也能复核的部分：《逆向》§7（复核方法）给出了每条关键结论的
字符串或键名定位，直接对解包目录做全文检索即可复现。

### 7.2 重新生成 `.doc` / `.pdf`

`.md` 是唯一修订入口；改完后按下列顺序重跑（脚本位于 `_san2/`）：

```text
python _san2/sanitize_deliverable.py     # 按映射规则重建全部 .md 产物
python _san2/_html_build.py              # .md -> 中间 HTML
powershell -File _san2/_word_export.ps1  # HTML -> .doc / .pdf
python _san2/_scrub_meta.py              # 清除作者等文档元数据
python _san2/_residual.py                # 残留敏感片段扫描（应仅剩占位符）
```

`_md2doc.py` 的 `convert(md, src_name)` 会按源文件名动态生成标题与页脚，
所以新增报告不必改脚本。

## 9. 分发纪律

1. **永不提交**：`_san2/_map_report.txt`（原值 ↔ 占位符对照表）、任何 `_re_ws/` 中间产物、
   原始 APK 与解包目录。对照表泄露等于脱敏作废。
2. **`.doc` / `.pdf` 是派生物**：修订只改 `.md`，再按 §7.2 重新导出；
   直接改二进制会造成三份内容不一致。
3. **本目录仍按「内部机密」流转**：脱敏只消除了身份与凭据，漏洞利用细节依旧可直接用于攻击。
4. 若要纳入版本库，建议最小 `.gitignore`：

```gitignore
_map_report.txt
_re_ws/
*.apk
__pycache__/
~$*.doc
```

> 另：`evidence/SHA256SUMS.txt` 内的摘要已替换为占位符，可安全提交；若后续补入新的摘要
> 或指纹文件，先确认已脱敏再 `git add`。
